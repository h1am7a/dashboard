# ТЗ: Telegram Mini App «Panel» — логика, контракт, хостинг

Версия 1.0 (2026-10-24). Заменяет PROMPT-v4 и раздел «Telegram Mini App» из SCHEMA.md.
Читать целиком перед началом. Если что-то противоречит — этот файл главнее.

---

## 1. Что строим

Однопользовательская панель на три экрана: **Today**, **Sleep**, **Body**.
Визуальный каркас уже согласован и лежит в макете — его не переделываем.

Панель **только читает** данные и делает одно действие записи: отметить задачу выполненной.
Всё остальное (метрики, тренировки, сон, замеры) вносится в базу ассистентом через CLI. Это не ограничение на будущее, а решение: один источник правды, никаких двойных путей записи.

## 2. Архитектура

```
Antigravity (локально)        GitHub              Сервер /root/priest
  frontend/  ──push──▶  репозиторий  ──pull──▶  web/dist  (статика)
                                                     │
                                              FastAPI :8099
                                                ├── /api/*   (JSON)
                                                └── /        (web/dist)
                                                     │
                                              cloudflared / tailscale funnel
                                                     │
                                               https://… → Telegram Mini App
```

Один origin для фронта и API — CORS не нужен вообще. Фронт ходит на относительные пути `/api/...`.

Почему так: Telegram открывает Mini App только по HTTPS с валидным сертификатом. Сервер за туннелем отдаёт и страницу, и API — значит mixed content и CORS не возникают никогда.

## 3. Структура репозитория

```
frontend/           # то, что делает Antigravity
  src/
  index.html
  vite.config.ts
package.json        # build → web/dist
app/                # backend: store.py, api.py
bin/life.py
db/life.db
docs/SCHEMA.md
```

Сборка: `npm ci && npm run build` → `web/dist`. Node нужен только на этапе сборки, в проде его нет.

FastAPI монтирует `web/dist` на `/` и API на `/api`. SPA-фолбэк: любой неизвестный путь без `/api` → `index.html`.

## 4. Контракт API

Все ответы — JSON, время MSK, даты `YYYY-MM-DD`. Ошибки: `{"error": {"code": "...", "message": "..."}}` с 4xx. Пустой массив вместо ошибки — запрещён.

### 4.1 Авторизация

Каждый запрос несёт заголовок `X-Init-Data` — сырую строку `Telegram.WebApp.initData`.

Проверка на сервере: `secret = HMAC_SHA256("WebAppData", BOT_TOKEN)`, затем `HMAC_SHA256(secret, data_check_string)` сравнивается с `hash`. Дополнительно проверяется `auth_date` (не старше 1 суток) и `user.id` из белого списка (`ALLOWED_USER_ID`).

Ответы: `401` — подпись неверна/просрочена, `403` — чужой user_id.
Для локальной отладки в браузере: если `DEV_USER_ID` задан в окружении и запрос пришёл с `127.0.0.1`, авторизация пропускается.

### 4.2 `GET /api/today`

```json
{
  "day": "2026-10-24",
  "weekday": "Saturday",
  "in_progress": true,
  "score": {"done": 0, "total": 5, "percent": 0, "items": [
    {"key": "sleep_ge_7", "title": "Сон ≥ 7 ч", "done": false, "type": "habit"},
    {"key": "task:1", "title": "Офтальмолог", "done": false, "type": "task"}
  ]},
  "sleep": {"hours": 6.0, "bed": "10:30", "wake": "16:30", "target": "14:30", "delta_min": 120},
  "mood": {"value": 6, "label": "Ok"},
  "hitmap": [{"day": "2026-10-24", "done": 0, "total": 5, "percent": 0}]
}
```

- `in_progress` — `true`, пока логический день не закончился (см. 5.1). Пока он `true`, панель пишет «4 / 6 in progress» и не называет день провальным.
- `sleep.hours`, `sleep.bed`, `sleep.wake` берутся из `v_daily` как есть. **Панель не вычисляет часы сна** — они уже посчитаны и лежат в `metrics`.
- `sleep.delta_min` — разница `wake_time` и `facts.wake_target` в минутах, положительная = позже цели.
- `hitmap` — последние 126 дней (18 недель) для верхнего блока.

### 4.3 `GET /api/sleep?days=7|30|90`

```json
{
  "period": {"from": "2026-10-18", "to": "2026-10-24", "days": 7},
  "avg_hours": 7.6,
  "avg_delta_min": 20,
  "target_hours": 7.5,
  "target_wake": "14:30",
  "series": [
    {"day": "2026-10-24", "hours": 6.0, "wake": "16:30", "bed": "10:30"}
  ],
  "prev_week": {"avg_hours": 7.1, "delta_hours": 0.5, "significant": true}
}
```

- `series` — по одному элементу на логический день, включая `null` у пропусков: `{"day": "...", "hours": null}`. Пропуск рисуется разрывом линии, не нулём.
- `prev_week.significant` — только при `|delta_hours| >= 0.5`, иначе панель дельту не показывает вообще.
- `avg_hours` считается по дням, где есть значение; в `period.days` — все дни периода.

### 4.4 `GET /api/body`

```json
{
  "measurements": [
    {"kind": "waist", "label": "Waist", "unit": "cm", "latest": 84.2, "date": "2026-10-23",
     "delta_cm": -1.1, "significant": true, "since": "2026-10-16", "cadence": "weekly",
     "history": [{"date": "2026-10-16", "value": 85.3}]}
  ],
  "thigh_asymmetry": {"date": "2026-10-23", "right": 58.6, "left": 59.1, "diff": -0.5},
  "workouts": [
    {"date": "2026-10-23", "kind": "strength", "duration_min": 50, "load": "hard",
     "note": "отжимания 5×10; изометрия 45/45/35 с; молотки 5×10 @9,7"}
  ]
}
```

- `measurements` — ровно четыре карточки: `waist`, `biceps_r`, `forearm_r`, `thigh_r`, в этом порядке. `thigh_l` карточкой не выводится, только в `thigh_asymmetry`.
- `significant: false` → панель пишет «no change» вместо числа (порог 1 см, точность ленты).
- `delta_cm` — с предыдущим замером, `since` — дата этого предыдущего замера.
- `workouts` — последние 8 недель для недельной полосы и детали дня.

### 4.5 `POST /api/tasks/{id}/done`

Единственная запись. Вызывает `store.close_task(id)`. Ответ `{"ok": true}`. Повторный вызов идемпотентен.

### 4.6 Прочее

`GET /api/health` → `{"ok": true, "version": "1.0"}`. Любой неописанный эндпоинт — `501`, не выдумывать.

## 5. Логика расчётов

### 5.1 Логический день

День начинается в **09:00 MSK** и заканчивается в 08:59 следующего календарного дня. Всё, что случилось в 03:00, относится к предыдущему дню. Причина: при сдвинутом графике «ночь с пятницы на субботу» — это один день, а не два.

`in_progress = true`, если текущее время в пределах логического дня сегодня.

### 5.2 Отбой, подъём, сон

- **`wake_time` = «встал»**, момент выхода из кровати. Не «проснулся». Именно он сравнивается с целью, потому что фаза дня двигается выходом из постели. Момент пробуждения, если известен, идёт в `note`.
- **`bed_time` = «лёг/вырубился»**, фактическое засыпание.
- **`sleep_hours`** = от `bed_time` до `wake_time`. Через полночь считается как `(24 − bed) + wake`. Значение уже лежит в базе в часах с одним знаком.
- Цель подъёма — `facts.wake_target` (сейчас `14:30 (цель подъёма)`). Парсить первое время из строки, не хардкодить.
- Окно подъёма — **±60 минут** от цели. Внутри — якорь выполнен.

### 5.3 Пункты дня (янкоря) и счёт

Пункт дня = активный якорь + задача, у которой `due` равен этому дню.

Якорь — запись в таблице `habits` с правилом; **панель его не отмечает**, выполнение выводится из данных:

| key | правило | что означает |
|---|---|---|
| `sleep_ge_7` | `sleep_hours >= 7` | сон не короче 7 ч |
| `wake_window` | `wake_time` в ±60 мин от цели | подъём в окне |
| `workout_day` | есть запись в `workouts` за день | была тренировка |
| `protein_ok` | `protein_ok = 1` | белок в первом приёме |
| `routine_eve` | `routine_ok = 1` | вечерняя рутина |
| `walk_30` (выключен) | `walk_min >= 30` | ходьба 30 мин |
| `routine_am` (выключен) | `routine_am = 1` | утренняя рутина |

- `score.percent = round(done / total * 100)`. При `total = 0` — `percent: null`, и панель пишет «нет данных», а не ноль. День без единой записи в базе — это «нет данных».
- Состав пунктов **меняется во времени**: у якоря есть `active_from` / `active_to`. Исторические дни считаются по тем якорям, что действовали тогда. Поэтому знаменатель у разных дней разный — и это нормально, сравниваем проценты, а не абсолютные числа.
- Пороги не сдвигаются под плохой день. Никогда.

### 5.4 Хитмап

- Одна клетка = логический день, сетка 12–18 недель, понедельник сверху.
- Заливка клетки — `percent` из API, пять градаций: `null` → без заливки и с рамкой («нет данных»), 0% → самый тёмный, далее по возрастанию яркости, 100% → самый светлый.
- **Кружок поверх клетки:** серый = в этот день была тренировка, по клику открываются детали дня и клетка становится белой (это выбранный/просматриваемый день). Кружка нет — тренировки не было.
- Будущие дни (после сегодня) контуром, не заливкой, и без кружка.
- Легенда обязательна и подписана полностью: none / 0% / 1–49% / 50–74% / 75–99% / 100%.
- `porn_count` в хитмапе не участвует никогда.

### 5.5 Замеры тела

- Талия — раз в неделю (воскресенье), бицепс/предплечье/бедро — раз в месяц.
- Дельта меньше 1 см — шум, показывается «no change».
- Бедро: карточка по правой ноге, под ней строка «L 59.1 · diff −0.5» из парного замера.

### 5.6 Настроение

Пять состояний, без цифр на экране: 2 — Bad, 4 — Meh, 6 — Ok, 8 — Good, 10 — Great. Лицо и подпись всегда согласованы.

### 5.7 Графики

- Обязательна фиксированная нижняя граница шкалы (сон — 4 ч). Шкала не подстраивается под данные.
- Значение ниже границы рисуется упором в неё с засечкой, реальное значение в подписи.
- Линия цели одна, подписана. Вторая пунктирная линия запрещена.
- Часы и время в таблицах — `tabular-nums`, по правому краю.
- Пропуск в данных — разрыв линии.

### 5.8 Запрещено

Стрики, ачивки, «дней без срыва», счётчик `porn_count`, кольца прогресса, чекбоксы у якорей, онбординг, уведомления, геймификация любых видов.

## 6. Экраны

**Today** — дата и день недели из API (не из разметки), `done / total` + «in progress», хитмап 18 недель с кружками, карточка сна (часы, отбой→подъём, дельта к цели; дельта в пределах ±60 мин нейтральная, вне — предупреждающая), настроение одним лицом с подписью, чеклист из `items[]` (у `habit` кнопок нет, у `task` — Done).

**Sleep** — переключатель 7/30/90, средний сон и дельта к прошлой неделе только при значимой разнице, три графика: сон (столбики, цель 7,5 ч), подъём (линия, цель 14:30), отбой (линия, цель 08:00), каждый со своей фиксированной шкалой и подписями оси.

**Body** — четыре карточки замеров, недельная полоса тренировок (три состояния: сделано / отдых / не наступило), деталь выбранного дня из `note` тренировки.

## 7. Хостинг без домена

### 7.1 Что нужно понимать

Telegram Mini App открывается только по **HTTPS с валидным сертификатом**. `http://` и самоподписанные сертификаты не работают. Домена у нас нет, покупать пока не обязательно — адрес можно получить у туннеля.

### 7.2 Варианты

| Вариант | Адрес | Стабильность | Цена |
|---|---|---|---|
| Cloudflare Quick Tunnel | `https://random-words.trycloudflare.com` | URL меняется при каждом рестарте | бесплатно, без аккаунта |
| Tailscale Funnel | `https://host.tailnet-xxxx.ts.net` | адрес постоянный | бесплатно, нужен аккаунт Tailscale |
| Cloudflare Named Tunnel | `https://panel.свой-домен` | постоянный | домен ~200–500 ₽/год + бесплатный план CF |

**Решение: старт на Tailscale Funnel** (постоянный адрес, без покупок), а Quick Tunnel — только для разовых проверок. Named Tunnel — когда появится домен; тогда адрес станет красивым и не будет зависеть от вендора.

### 7.3 Установка туннеля

```bash
# Tailscale (рекомендуется)
curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
tailscale funnel --bg 8099        # выдаст https://<host>.<tailnet>.ts.net

# Или разовый Cloudflare Quick Tunnel
curl -L -o /usr/local/bin/cloudflared \
  https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
chmod +x /usr/local/bin/cloudflared
cloudflared tunnel --url http://127.0.0.1:8099
```

`tailscale funnel --bg` переживает рестарты. Cloudflare Quick Tunnel — нет, поэтому только для теста.

### 7.4 Сервис приложения

`/etc/systemd/system/priest-panel.service`:

```ini
[Unit]
Description=priest panel
After=network.target

[Service]
WorkingDirectory=/root/priest
Environment="ALLOWED_USER_ID=<telegram_id>"
Environment="BOT_TOKEN=<token>"
ExecStart=/root/priest/.venv/bin/uvicorn app.api:app --host 127.0.0.1 --port 8099
Restart=always

[Install]
WantedBy=multi-user.target
```

Слушать только `127.0.0.1` — наружу торчит туннель, а не порт. Порт 8099 в файрволе закрыт.

### 7.5 Бот и кнопка

1. `@BotFather` → `/newbot` → токен в `BOT_TOKEN`.
2. `@BotFather` → `/newapp` (или Menu Button) → URL из туннеля.
3. Свой `user_id` (узнать у `@userinfobot`) — в `ALLOWED_USER_ID`. Один пользователь, чужие получают 403.

### 7.6 Обновление и данные

- Деплой: `git pull && npm ci && npm run build && systemctl restart priest-panel`.
- Бэкап базы: ежедневно `cp db/life.db backups/life-$(date +%F).db`, хранить 14 дней. SQLite, одна таблица на панель — потерять нечего, но и терять не хочется.
- Логи: `journalctl -u priest-panel -n 100`.
- Секреты — только в `Environment=` юнита или `.env`, в репозиторий не попадают.

### 7.7 Локальная разработка

`npm run dev` на ноутбуке, в `vite.config.ts` прокси:

```ts
server: { proxy: { "/api": "https://<туннель>.ts.net" } }
```

Фронт видит те же пути, что в проде. Если нужен обход авторизации — `DEV_USER_ID` на сервере и запрос с `127.0.0.1` через SSH-туннель.

## 8. Приёмка

1. Три экрана, тёмная тема, навигация Today / Sleep / Body.
2. Цифры совпадают с `./bin/life.py get`, `./bin/life.py score`, `./bin/life.py hitmap 14`, `./bin/life.py measurements`.
3. `grep -rn "mock\|fixture\|Math.random\|data.ts" src/` — пусто.
4. Нет своих таблиц, миграций, DDL. Нет вычислений процентов и дельт на фронте.
5. Один origin: фронт и API на одном адресе, CORS не настроен вообще.
6. `X-Init-Data` проверяется; без него — 401; чужой id — 403.
7. Пустая база → «нет данных» на каждом экране, без нулей и падений.
8. Кнопка Done у задачи работает и идемпотентна; у якорей кнопок нет.
9. Приложение открывается по https-адресу туннеля из Telegram на телефоне.
10. В репозитории нет токенов и `life.db`.
